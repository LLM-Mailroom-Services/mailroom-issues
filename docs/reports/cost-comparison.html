Bottom line.

  • Per document, the self-hosted Qwen3-8B-AWQ specialists on Modal L4 are cheaper than every hosted model for corporate records and correspondence.
  • They cost more than the cheapest hosted model for contracts, insurance claims and merger agreements.
  • Quality is the stronger argument against Modal today: a hosted model scores higher on 3 of the 4 tasks scored alike.
  • The sorter is decided on cost: ModernBERT matches the best hosted LLM sorter's document-type accuracy at about three orders of magnitude lower cost per document.

3. When does Modal pay off? Break-even and the optimal scenario#

Every comparison here is per completed document, because that is what the mailroom pays for.

Which model runs where. The only model self-hosted on Modal is Qwen3-8B-AWQ (vLLM, 4-bit AWQ). Every hosted model, including the pipeline's production model Qwen3.7-Flash, ran only through the API. §3.1 and §3.3–3.5 therefore compare Modal against the cheapest hosted model, which is a different model; §3.2 holds the model fixed and compares only the route.

  • Modal $/doc is the measured busy-window GPU cost of the run: replicas × $0.80 per L4-hour × wall time ÷ documents.
  • API $/doc is list price × the tokens each leg recorded.
  • Why per-token prices rank the routes differently (GPU report §3): each leg sends its own prompts, so one document costs a different number of tokens on each route. Per document is the comparison that decides deployment.

Three measured quantities turn that per-document floor into a deployment decision:

  • A warm fleet bills $0.80 per L4-hour whether it is busy or not.
  • A cold start bills the L5 boot (216 s deploy → ready) plus the 120 s scale-down tail on every replica: $0.075 on 1×L4 and $0.149 on 2×L4.
  • A second L4 doubles throughput at a flat cost per document: S2a $0.000211 vs S2b $0.000205 on the same 100 documents. A 1×L4 fleet therefore serves at the same $/doc for half the $/h.

Cells marked † apply that measured result to a fleet size the class was not run on.

Modal wins where it is cheaper per document than the cheapest hosted model and scores at least as well as that model, so replacing it loses nothing. It becomes cheaper at either of two break-evens:

  • Warm fleet: a sustained load of at least fleet $/h ÷ API $/doc documents per hour, which is a busy share of at least Modal $/doc ÷ API $/doc.
  • Cold batch: at least cold cycle ÷ (API $/doc − Modal $/doc) documents per start.

3.5 The optimal scenario#

  • Optimal: corporate records on self-hosted Qwen3-8B-AWQ, 1×L4 (sand032-s10-corporate75-v2, v2 prompts). $0.00039 per document against Qwen3.7-Flash via the API at $0.00079: 50% cheaper, $0.392 saved per 1,000 documents, at a score of 0.469 against 0.418.
    • Warm: one L4 ($0.80/h) beats the API from 1,018 docs/h sustained (50% busy) up to its measured 2,034 docs/h. Above that, a second L4 keeps the same $/doc; its break-even is 2,037 docs/h.
    • Cold: scale-to-zero batches beat the API from 191 documents per start on 1×L4 (381 on 2×L4).
    • Below both thresholds the hosted model is cheaper: idle GPU hours or the cold cycle cost more than the per-document saving.
    • Prompt caveat: the v2 corporate records prompt was marked HOLD in the v2 promotion run (paired Δ −0.0104 against production). On the production prompts the best winning configuration is sand032-s9-corporate50-bal at $0.00043 per document (45% cheaper, score 0.439).
  • Cheaper but lower quality: correspondence. Modal saves up to 68% per document (sand032-s3-corr50), but its best score here is 0.345 against Qwen3.7-Flash's 0.493. Take it only where that quality gap is acceptable.
  • Cheaper but lower quality: insurance claims. Modal saves up to 15% per document (sand032-s10-insurance75-v2), but its best score here is 0.688 against Qwen3.7-Flash's 0.773. Take it only where that quality gap is acceptable.
  • Never on Modal: contracts. The cheapest measured configuration costs 1.50× Qwen3.7-Flash per document even when fully busy (and the two legs are scored differently), so no volume or batch size recovers it.
  • Never on Modal: merger agreements. The cheapest measured configuration costs 1.20× Qwen3.7-Flash · frozen per document even when fully busy, so no volume or batch size recovers it.
  • Sorter. The Modal LLM sorter (S6) costs 2.05× the cheapest hosted sorter (Qwen3.7-Flash, $0.00085) at 89.5% against 91.0% accuracy. ModernBERT costs $0.0000010 per document at 95.0%, so neither LLM route is the sorter to deploy.

6. Caveats#

  • Draws differ. Modal: 50 documents per class on revision ed7576b6 (split all). API: 20 per class (Qwen3.7-Flash 50) on 46a4d3c2, train split. The per-class means are comparable in scale, not paired.
  • Prompts differ. The Qwen3.7-Flash legs ran eval-environment's mutated lineage. The other API legs and the Modal runs ran the frozen production prompts, and the Modal merger run used the MAUD prompt.
  • Contracts are not like-for-like. The Modal point is per-document CUAD category-presence F1. The pipeline rubric returns no score on label-native CUAD ground truth, so the API points use that rubric instead.
  • Busy-window Modal cost is a floor. The MAUD merger run's summary row, which includes its 122.8 s boot, is 28% higher than its run report. This is documented as a hub data-quality issue.
  • eval-environment files one merger leg under Qwen3-8B, but the logged model is qwen/qwen3.7-flash with the frozen prompts. These reports label it by the logged model ('API · Qwen3.7-Flash (frozen prompts)'), so there is no Qwen3-8B merger point.
